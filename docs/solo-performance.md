# 单人出演性能验证

验证日期：2026-11-06。版本：1.1.13。

正式发布版本 1.2.0 沿用下述已验证的筛选实现；本页保留实际测量时的测试版版本号。

## 最终实现

- 未启用单人筛选时，只保留原站请求，不自动预取、不扫描、不在后台刷新单人缓存。
- 普通请求直接返回原站同一个 Promise，不通过脚本的 async/await 转接响应；只在原站完成渲染数据后记住已有列表。此项已通过独立回归测试，不把一次浏览器等待直接归因于它。
- 开启时复用最近 30 秒内原站同一搜索条件已加载的作品及分页数据，不额外预读。
- 若已有数据足以组成完整首屏，先显示首屏；若原站已给出整个小结果集，可直接得到单人总数。
- 其他情况优先用小请求补首屏，同时按已知总量均分源分页。所有源请求共用最多四路并发，按原站顺序合并。
- 查询条件改变、关闭筛选或离开列表会取消未完成的请求。完整结果保持五分钟、最近三组的本地缓存；个人标记独立刷新当前页。
- 首次整组统计的源请求也将 `withPlaylistStatus` 置空，避免为整组作品读取收藏夹标记；只有覆盖当前显示页的少量源分页使用原站个人标记参数。前述接口基准没有包含个人标记的后台补读，也不能证明一次真实浏览器等待具体由哪个服务端查询造成。

均分页大小与并发均只在用户开启筛选后生效。源接口每次返回的是作品资料，不请求音频或封面文件。

## 对照测量

测量的是脚本筛选数据就绪的耗时，不包含点击控件、Vue 渲染、封面加载或整页刷新耗时。脚本结果缓存未参与，两种加载器共用同一份普通列表首屏数据。同一组测量顺序执行，避免互相抢占带宽；网络、服务端缓存和负载仍会造成波动，不是保证延迟。

“修改前”是 1.1.10 的源加载器（首批 100 条、后续逐步增长到 400、两路并发）。“修改后”是最终的按总量均分、最多四路的加载器。

| 声优 / 接口 | 修改前首屏 | 修改后首屏 | 修改前完整统计 | 修改后完整统计 | 请求数 | 单人数量 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| 逢坂成美 / api.asmr.one | 659 ms | 872 ms | 2829 ms | 1363 ms | 5 → 4 | 690 |
| 柚木つばめ / api.asmr-200.com | 679 ms | 657 ms | 4549 ms | 2929 ms | 7 → 4 | 1138 |

两组全部作品 ID 的有序序列 SHA-256 在前后实现中一致。完整统计分别缩短约 52% 和 36%；不能由这两组样本推断所有声优、接口或网络都同样变快。首屏没有稳定的普遍加速结论。

手动复测当前版本（访问公开 API，不读取浏览器登录令牌）：

```powershell
node scripts/benchmark-solo.mjs 逢坂成美
```

可选第二个参数是旧加载器模块文件路径；有旧模块时可对照。可选第三个参数为脚本支持的 API 地址。基准脚本不在 `npm test` 中自动执行。

## 接口核对与仍存在的限制

原站前端：<https://asmr.one/js/app.c5f7e7ac.js>。核对其搜索构造、声优目录请求及已注册的搜索提示类型。

公开接口的小样本验证结果：

- `/api/vas/` 中声优只有 ID、名称、全部参演数及翻译，没有单人总数或作品出演关系表。柚木つばめ的全部参演数为 1758，完整读取后的单人数为 1138。
- 在同一声优搜索中添加 `$vacount:1$`，接口仍返回原来的 1758；未知搜索词被忽略，不能把 HTTP 200 当作筛选生效。
- `$va:^柚木つばめ$`、`$va:%$` 没有按正则或 SQL 通配符匹配声优，不能用它们构造“排除其他所有声优”的快捷查询。
- `order=vas_count` 返回参数校验错误。
- 分页 999 已验证可用，1000、2000 返回 `pageSize` 校验错误。此前只验证到 500，后续边界测试确认 501、999 也有效，所以最终按总量选大小，不把 500 当作上限。
- api.asmr-100.com、api.asmr-200.com 也验证接受 500；运行时若镜像拒绝页大小，则按 500、400、100 逐级回退；若镜像实际截小返回数量，则按实际数量重新安排源分页。

这些核对没有发现可用的服务端“出演人数等于 1”筛选或轻量出演索引；不构成不存在任何未公开接口的证明。

因此，在已核对的接口下，第一次对任意声优同时获得“精确单人总数、完整随机跳页、与原站单次小分页相同的响应成本”仍然需要服务端支持。浏览器必须读取尚未知晓的出演名单才能准确统计。要消除这项全量成本，需要原站增加出演人数筛选及过滤后总数，或维护独立、及时更新的服务端出演索引。

源码检查、离线测试验证了未开启零单人请求、已有首屏复用、四路并发上限、镜像大小回退、乱序响应合并、缓存/账号隔离、精确分页与取消请求。API 基准不替代安装到浏览器后的交互验证。

## 浏览器验证

已在实际 Chrome / Tampermonkey 中确认运行 1.1.13。以逢坂成美切换到未在本轮使用的发售日期顺序进行筛选，完整结果为 690 部；普通页为 20 部，第 35 页为 10 部。测试后恢复原来的发售日期倒序、第 5 页，仍为 20 部、总数 690，未处于整理状态。

浏览器自动化等待发生过超时，但随后读取的页面正常且没有脚本错误；因此本轮不把工具等待时间当作可靠的画面延迟，也不宣称已经验证所有情况下首屏都更快。17 项离线测试及构建一致性检查通过。
